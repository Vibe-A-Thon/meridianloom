The fuller scaffold already built (five tree views, twelve commands) is **retained** — F0-A task 1's three commands are a minimum subset, and the extra commands/views are already tested; removing them would destroy working, tested value.
  - S0 Workstream C (worktrees, M18) moves to F1 (hosted agents only). S0 Workstream D (ledger) becomes F0 Workstream B — next up. S0 Workstream E (replay M27 → F4+; Simulation Core M32 → F3, as the regression harness). S0 Workstream F (`meridian doctor`) is F0-A task 6.

- **D20 (closed).** First-class observers in F0: Claude Code (OTel export → `Co-Authored-By` trailers → filesystem inference) and Copilot (SCM/PR API), exactly as `gaps_implementation.md` F0-D mandates. - **D23 (closed).** Trailer mechanism default: **`commit-msg` git hook**, opt-in, visible in the UI, removable in one action; `git notes` is the fallback for repositories where hooks are unavailable. Reasoning: AC-33 requires `git log` to still show trailers after uninstall — commit-message trailers satisfy this unconditionally; git notes are not shown by default and do not travel with `git push` unless the remote is configured for them, so they cannot be the default. The hook approach is also what the F0 plan text describes first.
- **D22 (deferred — human-gated).** See "Deferred with reason" below.
- **D24 (closed).** FR-M37-04 agent-vs-agent `llmRatio`: the ledger carries no per-line authorship data, so `llmRatio` is defined as the agent's share of the story's recorded token throughput (tokens_in+tokens_out over all in-scope entries for the story), unknown when the story records no tokens. Definition documented in `core/meridian_core/metrics/compare.py`.
- **D25 (closed).** FR-M37-05 J-curve dip definition: dip = contiguous below-baseline after-adoption weeks **starting at the adoption week** (a later slump is not the J-curve); depth = (min dip throughput − baseline)/baseline; empty weeks inside the observed span count as zero throughput; `recoveredWeek` null = not yet recovered (a fact, not a failure). Statuses: `ok` / `partial` (one-sided) / `insufficient_evidence` (empty sample).
- **D26 (closed).** FR-M37-07 tokenmaxxing rule: series split in half; flagged when recent/previous spend ≥ 1.25 (default) AND mean recent yield ≤ mean previous yield. Fewer than 4 periods, zero previous-window spend, or a missing yield half ⇒ `insufficient_evidence`/`unknown`, never flagged. Spend interface is `SpendPoint`/`YieldPoint` + `SpendSeries` protocol in `core/meridian_core/metrics/spend.py`; the `trust/tokenmaxxing` RPC takes `spendSeries` (agentId → periods) and derives per-ISO-week yield from the ledger — F1-F task 26's M39 real-spend feed adapts onto this protocol.
- **D27 (closed).** FR-M37-08 DORA proxies, because the ledger records no deploy event type: deployment frequency = approved diffs/week; lead time = median story first-diff→first-approved hours; change failure rate = approved diffs later carried by a rejection entry; time to restore = median failure→next-same-story-approval hours. Proxies are documented in the export's descriptions/notes. Unknown keys export an OTLP data point with `meridian.evidence=unknown` and **no value** — never an invented zero. OTLP/JSON encoding is stdlib-only; an `exportedAt` parameter keeps exports deterministic under tests.
- **D28 (closed).** FR-M39-03 forecast method: least-squares line over the trailing `windowMonths` (default 3) calendar months, zeros included (a silent month is evidence of no spend), evaluated at the current month; <2 evidence months ⇒ `insufficient_evidence`; negative projections floor at 0.
- **D29 (closed).** FR-M39-02 ceiling config home: `budgetCeilings` in the governance policy pack — added `usdPerAgent`/`usdPerMonth` alongside the existing `usdPerStory`; `usdPerSession` is contracted but unused in v1.
- **D30 (closed).** FR-M39-03 status precedence: `actual_breach`/`forecast_breach` outrank `insufficient_evidence` — the alert is the point of the requirement.
- **D31 (closed).** FR-M39-01 team/cost-centre source: new `policy/stories.yaml` story-metadata pack (FR-M26-03 attribution) with workspace override, `*` wildcard default, and an inline `storyMetadata` RPC param merged over the pack; unmapped ⇒ `unknown`, never fabricated.
- **D32 (closed).** FR-M39-01 recorded vs estimated cost are never blended silently: every aggregate carries `recordedCostUsd` (ledger `cost_usd`) and `estimatedCostUsd` (tokens × pack rate where cost was absent) separately, plus `costUsd` as their sum (best-known bill) and `estimatedShareUsd` at ceiling/forecast level.
- **D33 (closed).** FR-M39-02 pause mechanism: the sidecar records a durable `spend_ceiling` ledger entry (FR-M10-08) and dispatches a `spend/ceiling` notification; the extension host pauses the hosted ACP session at its next checkpoint. ACP 0.4.5 has no pause primitive, so "pause at checkpoint" is honest **turn-boundary enforcement**: the notification marks the session pause-pending (`SpendCeilingPauseTracker`, `extension/src/governance/spend-ceiling.ts`, b4022e9 — nothing cancelled mid-flight, unlike gate.halt's process kill), the in-flight turn runs to its stop reason, and the next turn is refused at `AcpClient.prompt`'s new `checkpointGate` option; the steer controller also refuses a pause-pending session. Observed/unbound sessions get advisory warnings only, never a fake pause (FR-M35-06). Resume re-runs sidecar `spend/ceilingCheck`; only a clean re-check releases the pause. Wired end-to-end at 539e564 (extension.ts notification subscription + launch.ts `checkpointGate` passthrough).

- **D43 (closed — fresh-workspace policy, N0-T09a).** Ship-and-copy on first run, with a visible notice. Uniformity rule (T09b): absent → scaffolded default (one behaviour); present-but-invalid → fail closed naming the file and the schema violation (second behaviour). No third behaviour may exist.
